# Codex token benchmark — 2026-09-22

In this controlled three-task location-search microbenchmark, `jgrep --ai -F`
used **16.4% fewer total Codex tokens** than `rg -F`. Non-cached input fell by
54.9%, and the text returned by the search tool fell by 97.1%.

| Metric (three tasks, one repetition) | `rg` baseline | `jgrep --ai` | Reduction |
| --- | ---: | ---: | ---: |
| Total tokens (input + output) | 91,278 | 76,334 | **16.4%** |
| Non-cached input tokens | 34,703 | 15,662 | **54.9%** |
| Search-tool output characters | 95,421 | 2,739 | **97.1%** |

The total-token difference was 14,944 tokens. Both arms ran exactly one search
command per task over the same archived source tree. The location lists agreed
for two tasks. In the broad `jgrep`-name task, the `rg` output contained the
correct fourth location, but its Codex response skipped that record and
reported the sixth record as the fifth; the `jgrep --ai` response returned the
actual first five. This difference is preserved rather than normalized away.

## Environment

- Source: commit `a5ed20a50de22fdf60f9756853dcf80f847aacab`
- Codex CLI: `0.154.0`
- Model: `gpt-5.6-luna`, low reasoning effort
- jgrep: `0.1.1`
- Repetitions: 1
- Tasks: fixed-string searches for `localjev-grep`, `jgrep`, and `semantic`
- Excluded from both searches: `benchmark/**`

The baseline command was
`rg --hidden --sort path -n -F -g '!benchmark/**' -- NEEDLE .`. The treatment
command was
`jgrep --ai --ai-max-results 25 -r --exclude 'benchmark/**' -F -e NEEDLE .`.
`AGENTS.md` was excluded from the temporary snapshot so repository guidance
could not select a search tool. Every Codex session was ephemeral and used a
read-only sandbox.

The full per-run prompts, commands, answers, and `turn.completed.usage` records
are in [`results/2026-09-22.json`](results/2026-09-22.json). The six raw Codex
event streams and their stderr companions are indexed in
[`logs/2026-09-22/README.md`](logs/2026-09-22/README.md). The reproducible
runner and task definitions are in [`run.sh`](run.sh) and
[`tasks.json`](tasks.json).

## Scope and limitations

This result measures the token effect of omitting matching source text and
bounding the location list in three broad fixed-string searches on one
repository snapshot. It does not measure semantic-search quality, end-to-end
coding quality, or latency. It is one repetition with one Codex model, so model
variance is not estimated and the percentage is not a general guarantee.
